# 突破路径与示例

## 选择操作，不只选择头衔

| 当前动作或假设 | 可借用的方法 | 必须交付或检验什么 |
| --- | --- | --- |
| 每次从头计算 | 增量计算、预计算、复用 | 性能变化与新鲜度、存储和失效成本 |
| 所有步骤都必须做 | 价值流分析、条件触发、删减环节 | 被删除步骤是否承担关键质量保证 |
| 只能等全部完成再反馈 | 渐进呈现、主动学习、序贯实验 | 关键不确定性是否更早消除，指标是否仍可比 |
| 只能逐个处理 | 批处理、并行、排队与调度 | 资源竞争、尾延迟和失败隔离 |
| 一直优化当前环节 | 重构输入、接口或上下游分工 | 成本是否被转移，整体结果是否改善 |
| 解释原因 | 调查采访、因果推断、法证式核查 | 可追溯证据、反例和解释无法覆盖的事实 |
| 促成判断或行动 | 决策分析、编辑、交互叙事 | 决策选项、取舍、真实样稿或可操作界面 |
| 让现场体验有效 | 舞台调度、动效、声音或3D原型 | 可演示片段、时间预算和真实受众反馈 |

只选择对当前问题有贡献的方法。把“分析师、记者、编辑”等头衔改成任务，如重算指标、核对原始证词、删去无证据的因果连接。需要红队时，要求其找出足以推翻推荐的反证，并用资料或测试核实；不能只生成一份批评意见。

## 深度：专业工作还缺什么

先补齐“遗漏的专业动作—原始资料—具体工具—外部判据”四项。选择最可能改变结论的缺口去执行。

例如流失分析：先核对事件定义和队列窗口，再按渠道、版本等检查解释；用数据库或代码复现，不只叙述汇总表。调查早期信号时，先限定预测时点，再检验信号在时间留出数据上的表现。小样本或模拟数据只能验证方法能否运行，不能证明真实业务有效。

## 工程：网站从10秒到0.2秒

把0.2秒作为重新设计路径的挑战目标，先找实现所需条件。明确原指标是首字节、首屏还是完整可交互，保留口径。

读取请求瀑布、服务端追踪、资源体积和冷暖缓存数据。根据瓶颈选择减少工作、预计算、消除串行依赖或变更交付架构。用相同内容、设备、网络和缓存条件复测。局部达标就报告局部条件，继续检验未达标场景；不要把一次局部失败宣布为普遍不可能。

## 高度：季度复盘的三层升级

1. 从填模板升级为解释变化、原因和行动；需要足够的业务上下文。
2. 从解释升级为决定：找出最迫切的决策，给出选项及支持、反对理由。
3. 从一次复盘升级为提前发现问题、辅助资源配置的机制；需要历史重放和前瞻并行验证。

明确要求的PPT仍交付；若用户授权重构复盘方式，可用更有效的机制取代原先暂定形式。不要因为能做仪表盘，就默认它比PPT更有效。持续机制的具体字段见主文件链接的工作流参考。

## 广度与创作：一场发布会

从具体动作寻找领域：让观众形成判断需要事实与证据，记住主张需要编辑与叙事，体验揭晓需要舞台或视听设计。选择真正影响体验的手段，交付可演示的关键片段。

创作目标已清楚时，直接把作品做深、拓宽表达方式；不必先把它改写成增长指标。用作品体现差异，区分作者自检与受众实测。保持预算、时长、品牌事实，不用“国际化、沉浸式、震撼”等形容词代替设计。

## 被“做不到”卡住时

- 检查依据是实际试验、物理下限，还是旧经验和当前工具习惯。
- 寻找成立条件不同的成功先例；验证能否迁移，不用故事代替证据。
- 选出最小的决定性实验，允许它失败，以结果更新假设。
- 检查大胆路线是否因不熟悉被过早淘汰，普通路线是否因容易交付被过早选中。
- 决定继续当前路线、修正局部实施或换机制；只有证据支持时才收缩目标。
