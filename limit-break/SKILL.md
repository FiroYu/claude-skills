# Limit Break · 限界突破

把看似不可能的目标变成值得检验的假设。主动寻找改变解题机制的路径，产出可用成果，并用证据说明究竟突破了什么。

## 执行原则

- 保持目标上的野心、方法上的开放和结论上的诚实。不要因熟悉的方案做不到，就断言目标做不到；也不要把“相信可行”当作证据。
- 在用户授权范围内直接推进。只对影响方向的关键缺口提问；其他缺口写明假设后继续。不先交一套流程等待用户批准。
- 根据任务选择动作，避免把每一步都变成长篇报告。简单任务在一轮中完成；复杂任务优先验证决定成败的瓶颈。
- 用户要求方案时，交付具体方案及最小验证；用户要求实施时，继续完成可执行的实现和验证。不要停在重新撰写提示词。

## 1. 把交付物改写为结果

用一句动词驱动的描述，明确：让谁在什么场景下发生什么变化，以及如何判断成功。追问一层“目标背后的目标”，但保留用户真正需要的交付物。

例如：把“做季度复盘PPT”提升为“让管理层在30分钟内看清变化、判断原因并作出三项资源配置决策”。若更好的工作机制能达成目标，可以提出并验证；不要擅自取消PPT。

区分常规基线、用户验收目标和更激进的挑战目标。只有量纲、分母和基线成立时，才提出倍数或数量目标；创作任务用受众效果和具体作品差异定义突破，不机械套用“10倍”。把挑战目标当作探索方向，不冒充达成承诺。

## 2. 找到真正限制结果的条件

优先定位一个主导瓶颈；证据不足时，把瓶颈判断标为假设并优先检验。把相关条件分为三类：

- **必须保留**：用户明确要求的质量、预算、期限、兼容性及其他硬约束。遵守已有权限与规则。
- **可以挑战**：惯常流程、既有分工、当前架构、默认工具、“大家都这样做”等未经证明的限制。
- **尚待检验**：缺少证据的因果判断、技术极限、受众偏好或资源假设。

选出最值得推翻的一条假设：如果它不成立，哪条原本被排除的路径会出现？不要通过换指标、换样本、减少承诺功能或隐瞒成本制造提升。需要改变硬约束时，把方案明确标为有条件成立。

## 3. 生成机制不同的突破路径

默认探索三条实质不同的路径：把现有方法做到极致、移除或绕过主导瓶颈、借用其他领域的方法重构问题。只保留有价值的路径；不要为凑数提供同一想法的三个版本。

对每条候选简要说明：改变什么机制、为什么可能产生跃迁、依赖什么条件、什么结果会推翻它。至少认真探索一条此前容易被认为“过于大胆”的路径。

跨领域借鉴必须落到可执行的操作，如排队论改变调度、信息论改变信息压缩、实验设计识别因果。不要停留于专家头衔、空泛类比或角色对话。

按潜在收益、约束适配和验证成本，选择最值得推进的一条。不要仅因成熟方案更容易验证，就淘汰收益更大的路径；对高潜力但不确定的路径，先做低成本的关键检验。保留一条机制不同的备选。

## 4. 用专家的方法获取证据

只补充与关键假设有关的原始资料、专业方法和工具，并尽快使用。优先查看源代码、原始日志、逐条反馈、原始文献或实际作品，而非只接受汇总后的解释。

把用户的判断当作待检验假设，同时寻找支持证据和最有力的反例。从原始材料中寻找常规解释遗漏、但可能改变方案的新信号。遇到相关性、历史回测或模拟结果，说明它们能支持什么，不能证明什么。

使用实际可用的工具。工具或资料缺失时，先完成不依赖它们的部分，并给出准确的数据需求或可运行验证材料；不要把想象中的调用写成已经完成的工作。任务需要最新事实时查证原始来源。

## 5. 尽快制造可检验的成果

围绕最关键的不确定性，构建一个最小但能说明问题的原型、实验、分析或作品片段。明确：假设、对照、观察指标、通过条件、失败条件；能实际运行就运行。

- 工程：运行实现，在相同负载、质量和环境下比较；检查边界条件及代价。
- 数据与业务：检查口径和混杂因素，采用留出数据或适当对照；不要让同一批数据同时承担发现与最终验证。
- 创作与沟通：先交付最有突破潜力的实际样稿，以任务标准检查，再用真实受众的理解、记忆、选择或行动检验。没有受众测试就标为待验证。

让运行结果、独立数据或真实反馈裁决。自我检查可以发现问题，不能替代外部验证。拿不到外部反馈时，交付最强的可审阅成果、可被推翻的预测和最低成本的验证办法，明确其未验证状态。

## 6. 根据反馈换路，再推进

实验失败后，先说明它推翻了哪个假设，再改变机制或决定性条件。不要只重复“再努力”，也不要反复润色同一方案。

在用户的时间和资源预算内迭代。未给预算时，先完成一个有信息量的验证循环；必要时再进行一到两次关键改动。仍有收益且资源允许时继续，不把轮数当成必须停止的理由。

达标、触及有证据的硬约束、关键外部依赖阻塞，或继续实验的信息收益明显低于成本时收束。失败时仍交付当前最佳成果、已排除的路径及下一项最值得做的实验。局部极限不能直接推广为普遍不可能。

## 交付方式

优先展示成果，再提供足以判断的依据。按任务合并为以下内容，不机械照搬标题：

1. **突破点**：目标、主导瓶颈、被改变的关键假设，以及相对常规方案的实质差异。
2. **可用成果**：推荐方案、实现、分析、原型或作品；让用户能直接使用或审阅。
3. **证据与代价**：实际做过的验证、可比结果、适用条件与主要成本。明确区分已验证、合理推断和待验证。
4. **下一步**：如有剩余不确定性，给出最有价值的一项动作及其通过条件。

不要为显得惊人而夸大结论，也不要为显得谨慎而退回泛泛建议。

需要换路却仍被常规方案束缚时，按需阅读 [突破路径与示例](references/breakthrough-patterns.md)。只读取与当前瓶颈有关的部分。
