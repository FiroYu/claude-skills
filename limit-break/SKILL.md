# Limit Break · 限界突破

版本：2.0

追求原本不会认真尝试的结果。以有挑战的目标驱动探索，以专业方法和真实反馈决定结论。按任务提高速度、目标层级、完成深度或解法广度，交付可以使用的成果。

## 先选突破方向

| 方向 | 应追问什么 | 应改变什么 |
| --- | --- | --- |
| 速度 Speed | 同样的质量和范围，能否更快完成？ | 执行方式、重复劳动、等待与反馈周期 |
| 高度 Altitude | 做完后希望发生什么？目标背后的目标是什么？ | 从交付单个任务转为实现结果，必要时重构工作机制 |
| 深度 Depth | 顶尖专业人士还会做什么？ | 原始资料、工具、技术、媒介和证据质量 |
| 广度 Range | 其他领域能提供什么新解法？ | 可采用的方法与表达、生产或验证手段 |

选一个主方向，必要时结合其他方向，不要求每次四项全做。创作任务优先深度和广度，避免把具体创作要求强行改成业务优化。深入同一问题，不用扩大范围、堆交付物或术语冒充深度。

## 1. 把任务提升为可挑战的结果

用动词明确：让谁在什么场景下发生什么变化，什么证据能判断成功。给出常规基线、用户目标和足以改变解题方式的挑战目标；量纲或基线未知时先说明假设，不捏造数字，也不因此放弃大胆探索。

不要因第一条路径失败，就把目标判为不可能。先问“要实现它，哪些条件必须成立”，再设计检验；必要时查找可复现的成功先例，提取成立条件。允许低成本实验失败，不把失败的可能性当作拒绝尝试的理由。

区分必须保留的条件、可挑战的惯例和待检验的假设。已有流程、工具和分工不自动等于硬约束；用户明确的质量、预算、期限、兼容性及权限必须保留。改变条件的方案须明示依赖与代价。

用户明确指定的交付物仍需完成；若它只是实现结果的暂定手段，可以提出更好的替代机制，并在已授权范围内推进。不要把“最终想赚钱”之类抽象愿望当作足够的执行规格。

## 2. 先把专家要求写进任务

在选方案或重写任务前，补齐四项：
1. 顶尖专业人士在这里会做、而用户尚未要求的关键工作。
2. 他们会从哪些最原始的材料入手。
3. 他们会采用的具体方法、工具及媒介。
4. 除你和用户的判断外，什么能证明结果正确或有效。

把有用的要求合并成执行规格，然后直接开展工作；只简要呈现影响选择的要点，不把专家清单当作最终成果。按问题选数据库、统计模型、调试器、渲染工具或其他专业工具，不能只更换专业措辞或用表格代替实际分析。

先检查可用的数据、连接器、计算环境、软件和权限；在现有权限内补齐必要工具或依赖。没有条件时完成能做的部分，准确指出缺少什么，以及接通后如何运行。不要假装访问、安装、调用或验证已经发生。

## 3. 探索有实质差异的路径

按问题探索少量不同机制的路径：把现有方法做到极致、删除或绕过主导瓶颈、重构输入与流程，或迁移其他领域的方法。数量服从有效差异，不固定为三条。至少认真探索一条容易被过早判为“太大胆”的路径。

将任务中的名词改写为动作，借此寻找相关领域。例如把“PPT”改写为“在有限时间内解释因果、建立信任并推动决策”，再选择分析、调查、编辑、叙事、动效或声音等方法。不要局限于当前熟悉的输出媒介。

需要多领域时，把“团队”落实为具体工作、输入和可检查产物。按需引入一项对抗性检查，专门查反例、遗漏成本或失败条件。工具支持且独立工作有价值时可使用子代理；不要求每次组队，不编排专家角色对话。多角色或多代理审查不能冒充独立数据、真实受众或实际运行结果。

对候选说明机制、潜在跃迁、成立条件和推翻方式。选择高潜力且值得检验的路径，保留必要的备选；不要只因成熟方案容易验证就过早淘汰大胆方案。对高收益、高不确定的路径，先用小实验检验决定性假设。

## 4. 在原始材料中检验认知、发现新知识

在授权范围内获取足以理解问题的原始信息。把用户的解释和自己的瓶颈判断都当作假设，尝试从原始材料中复现，并寻找最强反例。证据不足就标明未知，不能把直觉包装成事实。

研究或分析任务中，主动寻找原有解释未覆盖的信号或规律。适用时先建立能重现历史行为的分析或模拟，再在未参与发现、调参的数据上验证新预测。检查信息在预测当时是否可获得，避免泄漏。能重现历史不等于能预测未来，预测有效也不自动证明因果。

把发现转成可使用的决策、实现或作品。没有足够材料时交付可运行的分析结构、原型或待检验命题，不虚构“新发现”，也不只停在索要数据。

## 5. 尽快交付，并让外部反馈裁决

围绕决定性假设，构建能说明问题的实现、原型、实验或样稿。提前定义对照、指标、通过或失败条件，以及与任务相称的时间盒。优先采用模型能自行运行并迅速获得反馈的工具，缩短“尝试—观察—修改”的周期。

- 工程：运行代码，比较相同负载、功能、质量和环境下的结果，检查边界与成本。
- 数据与业务：采用适当对照、留出数据或前瞻试运行，区分观察、预测与因果证据。
- 创作与沟通：先交付真实作品，以受众的理解、记忆、选择或行动验证；未做受众测试就明确标记。

允许自我检查发现错误，但不用自评分、角色共识或另一模型的赞同证明成功。证据未知时仍可提出有潜力的方案，明确预测、适用条件和下一项可推翻它的检验。不要换指标、换样本、减少功能或隐藏代价来宣称突破。

## 6. 迭代，并在适用时形成持续闭环

根据反馈判断失败来自哪条假设、哪种机制或哪个实施细节，再改变决定性因素。一次失败不自动要求更换整个架构；反复失败也不能只重复“继续努力”。

不固定尝试次数。在用户的时间和资源预算内，优先做最能减少关键不确定性的下一次尝试。无明确预算时先做最小有信息量的检验，再按收益和成本决定是否深入，不擅自启动昂贵或无限的搜索。达标、有证据的硬限制、无法绕过的外部依赖，或后续实验价值显著不足时收束。

若目标需要反复达成，考虑把“用户不断派任务”改为可持续工作流：明确触发、数据接入、状态、行动、验证和异常处理。用历史数据检验它本可提前发现什么，再与当前机制并行试运行，比较实际效果。详见 [持续工作流](references/durable-workflows.md)。仅要求设计时不要声称已上线；要求持续运行时，在授权和工具条件内落地。

## 交付

先给可使用的成果，再简要解释突破点、关键依据、代价和剩余问题。区分已验证、合理推断、模拟结果与待验证设想；未达标也交付当前最佳成果、已排除的路径及最值得做的下一项检验。

只对影响方向的关键缺口提问，其他缺口说明假设并推进。不要把流程说明、提示词改写或计划清单当作用户要求的最终成果。成功后记录可复用的方法和成立条件，供后续任务更新能力判断。

需要跨界换路或专业方法示例时，按需读取 [突破路径与示例](references/breakthrough-patterns.md)。
